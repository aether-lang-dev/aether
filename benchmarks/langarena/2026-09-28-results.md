# LangArena #1986: remeasurement and actor scaling

The packed-float cluster no longer supports the original claim that Aether
needs distinct array handle types to approach Go's throughput. With the
current compiler, single-threaded Matmul, Nbody, and Spectralnorm are close
to Go on this host. The sequential T4/T8/T16 port and NeuralNet still differ
from their Go implementations.

## Method

- Intel Core i7-1265U, Linux 6.6.119 under KVM, 12 online processors.
- Aether `682460bde13430046f175aaa0b89354d61a929a9` (0.736.0), freshly
  rebuilt, default `ae build` (`-O2`), GCC 12.2.0.
- Go 1.24.5, default `go build -buildvcs=false`.
- Unmodified LangArena `add-aether-benchmarks` at
  `5adbe231b662d83c066d662822728560c2cdbd30`.
- All seven small-input checksums passed. Five production runs per language,
  alternating language order; all 70 production checksums passed. The suite's
  original inputs, iteration counts, warmups, and timing boundaries were retained.
- Ratios below divide the median Aether time by the median Go time. This is a
  same-host comparison, not a reconstruction of the original historical build.
  No new runtime fixes were in these LangArena binaries; those benchmarks do
  not spawn Aether actors.

[Individual samples and binary hashes](2026-09-28-samples.json) are retained.
[The driver](README.md) reproduces the procedure. Thermal and VM scheduling
variation remain: for example, Aether's single Matmul ranged from 4.035 to
5.303 seconds. Small differences around parity are not evidence of a stable
language ranking. This subset does not establish a new 50-task geomean.

The generated C includes `aether_arr_inline.h`; disassembly of the Aether
benchmark contains no calls to `floatarr_get_unchecked` or
`floatarr_set_unchecked`. This confirms visibility of the accessor bodies,
not vectorization of every loop. No fast-math flags or floating-point
reassociation were enabled.

## Two runtime obstacles to the actor example

Adding the [actor matmul example](../../examples/actors/matmul.ae) exposed
two independent problems that kept an otherwise parallel program serial:

1. x86 core detection used CPUID leaf 1's **per-package** logical processor
   count. This VM reports 12 sockets with one processor each, so the scheduler
   started one worker thread. Detection now prefers the OS's online processor
   count, retaining CPUID as a fallback and the existing 16-thread cap.
2. `scheduler_spawn_actor(-1, ...)` converted a main-thread spawn's absent
   core preference to core 0. That bypassed the balancing logic already in
   `scheduler_register_actor`. Main-thread spawns now reach that logic with
   `-1`. Explicit placement and scheduler-thread parent–child locality remain
   intact. NUMA allocation uses CPU 0's node when placement is not yet selected.

Fixing core detection alone started 12 threads but still left the work on
core 0. Both fixes were needed for the following result. Each row is the
median of five 900×900 multiplies with the same pool, with every output cell
checked against an independent serial reference after every repetition:

| Worker actors | Before both fixes (ms) | After both fixes (ms) |
|---:|---:|---:|
| 1 | 416.5 | 402.2 |
| 4 | 441.6 | 163.7 |
| 8 | 540.2 | 100.1 |
| 16 | 496.7 | 98.0 |

With eight workers, the fixed runtime was about 4× faster than one worker
in this run. These are **example kernel timings**, including dispatch and
completion but excluding allocation, transpose, and validation. They must
not be compared directly to LangArena's multi-iteration totals above. Worker
count cases ran sequentially in ascending order; treat scaling as directional.

Regression checks cover synthetic package/OS counts and the cap/fallback,
actual spawn placement, explicit affinity, parent locality, every output cell,
uneven partitions, more workers than rows, and repeated buffer/pool reuse.
They assert correctness and placement, not elapsed-time thresholds.

## Remaining port work

LangArena's Aether T4/T8/T16 cases still call its serial matmul. The example
provides a validated pattern for replacing them, but this change does not
modify that separate repository.

For NeuralNet, the Go implementation stores each neuron's incoming and
outgoing connections. The Aether implementation scans all 30 synapses for
each activation/update and again for each hidden neuron's error. That is
concrete additional work in the port. It is a candidate explanation for the
remaining gap, not a measured attribution of the entire 2.91× difference;
matching the adjacency traversal is the next experiment.

Distance::NGram and integer-keyed maps remain separate work. These results
do not measure them or justify expanding the array type system.
