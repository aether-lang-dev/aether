# tests/leaks_known.txt — known-acceptable leak counts for the macOS
# leaks(1) gate (tests/run_macos_leaks.sh). Every regression program is
# expected to report ZERO leaks; the entries below are the audited
# exceptions, each capped so a regression that grows the count still
# fails the gate.
#
# Two columns: <test_name> <max_leaks>. Lines starting with '#' and
# blank lines are ignored. Keep the rationale next to each entry.
#
# ── ARTIFACT: third-party library process-globals ───────────────────
# Reclaimed at process exit, NOT reclaimable by us. Proven false
# positive: leaks(1) --atExit samples the heap BEFORE atexit handlers
# run, so OpenSSL's OPENSSL_cleanup (registered via atexit) has already
# been scheduled but not yet executed at sample time. The memory IS
# returned to the OS at exit. Confirmed: an explicit atexit(OPENSSL_cleanup)
# changed the leaks count by zero.
test_cryptography_hmac_md4_md5 122

# test_rsa_pkcs1 and test_closure_local_shadows_promoted_capture used to be
# listed here (caps 130 and 1). Both report 0 on the macOS ARM64 CI runner and
# locally (measured 2026-10-07 over four CI runs), so they are held to 0 like
# every unlisted test: a cap far above the real count would let a new leak of
# that size through unnoticed.

# The closure UAF fix (a heap string allocated in a closure and published
# through a captured cell) reclaims the string correctly now — the prior
# per-iteration leak is gone. The residual is one bounded env-cell-plus-string
# per seq_each/fs.walk call: those are EXTERN callbacks, so the codegen cannot
# prove the callee does not retain the boxed closure and conservatively does
# NOT drain its heap env after the call (leak >> UAF; awaits a `@retains`/
# transient-extern annotation to opt in). Bounded (does not scale with element
# count), and unrelated to the value-correctness this test asserts.
# Measured 15 on every CI run (2026-10-07), so capped there, not at 20.
test_closure_local_alloc_capture 15
