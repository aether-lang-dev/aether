- **`ae version install`, `ae upgrade`, `ae add` and `get.sh` now survive GitHub's release-download endpoint failing.** `https://github.com/<repo>/releases/download/<tag>/<asset>` is served separately from the REST API, and on 2026-11-09 it answered HTTP 504 for every aether asset while the same assets downloaded fine through the API. A release-asset download that fails is now retried through `api.github.com` (look the asset up in `/releases/tags/<tag>`, then fetch `/releases/assets/<id>` as `application/octet-stream`), unauthenticated unless `GITHUB_TOKEN` or `GH_TOKEN` is set, which is then sent as a Bearer token. The sha256 `digest` the API lists is checked against the download, and when both routes fail the error says so. `AE_GITHUB_WEB_BASE` and `AE_GITHUB_API_BASE` move the two endpoints, which is how `tests/integration/ae_download_api_fallback` forces the first to 504.
