- **A wider seccomp filter under the sandboxed spawns.** Past the process-creation fence it now refuses, however the call is made: an `AF_INET`/`AF_INET6` socket unless there is a tcp, udp or listen grant (`AF_UNIX` passes); `execve`/`execveat` unless `grant_exec`; `ptrace`, `process_vm_readv`/`writev`, `bpf`, the mount family (old and new API), `pivot_root`, `setns`, a new namespace by `clone` or `unshare`, the keyring calls, `userfaultfd` and `perf_event_open`; and `io_uring_setup`/`enter`/`register` get `ENOSYS` so callers fall back. The child's own exec of its program still passes: without `grant_exec` the spawn's filter allows only an `execve` of the exact pointer the child passes, and the preload's constructor then adds a second filter that refuses every further exec (`AETHER_SANDBOX_NO_EXEC=1`), before the program's code runs. The tables cover x86_64 (with i386 and x32), aarch64 (with 32-bit ARM), riscv64 and loongarch64, each checked against the kernel headers. `clone3` now gets `ENOSYS` even with `grant_fork`, so the namespace check on `clone` cannot be skipped, and with `grant_fork` the filter is installed too (it used to be left out).
