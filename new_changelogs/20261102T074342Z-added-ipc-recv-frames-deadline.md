- **`std.ipc` gains one receive, frames, a deadline, and a direction rule for descriptors.** `ipc.recv(ch, max)` returns `(data, fd, err)` from a single `recvmsg`, `fd` being `-1` when the message carried none, so a peer no longer announces a descriptor before sending it (`read` drops one riding on the bytes and `recv_fd` refuses a message without one; both are unchanged). `ipc.write_frame` / `ipc.read_frame(ch, max)` carry length-prefixed messages (a 4-byte big-endian length, any bytes, `max` a hard cap checked on the header before anything is allocated), the reader written once and holding no state between calls. `ipc.wait_readable(ch, ms)` is `poll`, and `ipc.read_frame_timeout` bounds a whole frame so a peer that stalls after a header cannot hold the reader. The parent end of an `os.run_socket` channel now refuses any descriptor its child sends, in `recv` and `recv_fd`: they are closed and an error returned, with no opt-in. The runtime records the parent ends, and `io.fd_close` forgets them. `wait_readable`, `recv`, and timed reads report that they are unsupported on Windows; the untimed frame calls work there.
