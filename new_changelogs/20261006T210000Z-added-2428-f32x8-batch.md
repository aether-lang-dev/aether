- **`f32x8` and `i32x8`: eight float lanes and their mask (#2428).** The
  `f32x4` surface at twice the width: `lanes.f32x8(...)`, `splat8`, `load8` /
  `store8`, `lane8`, `sum8`, `min8` / `max8`, `select8`, `sqrt8`, `abs8`, the
  comparisons, `mask8_and` / `mask8_or` / `mask8_not`, `any8` / `all8`, and
  slice-checked `load8_slice` / `store8_slice`. Operators work as on `f32x4`.
  With `-mavx2` in aether.toml's `[build] cflags` an `f32x8` is one 256-bit
  register; without it, two four-lane halves held in two registers. Measured
  on an eight-term polynomial kernel (i7-13700K): 50 ms against `f32x4`'s 98
  ms under AVX2, and level with `f32x4` without it. Lane writes (`v.x = 1.0`)
  work as on `f32x4`, and the AVX2 form is declared 16-byte aligned, the
  alignment a slice or closure environment on the heap has, so it is never
  moved with an aligned instruction that would fault there.
- **`list.get`, `collections.list_get` and `json.array_get` report an
  out-of-range index as an error (#2439).** They returned `(null, "")`, which
  the `(value, err)` convention used everywhere else in std reads as success.
  They now return `(null, "index out of range")`. A caller that bounds its
  index by the size behaves as before; `list_get_raw` and
  `json_array_get_raw` stay the unchecked forms.
- **`x op= y` on a variable a closure captures by reference changes the
  value.** The variable lives in a shared cell whose C name is the cell's
  pointer, and `x += 1` was emitted as is: pointer arithmetic, so the value
  never changed and the next read was of the wrong memory, with no
  diagnostic (a closure printed 0 where 30 was due). It now writes through
  the cell, as `x = ...` does. The same target was missed by closure capture
  analysis, so a closure whose only use of a variable was `+=` failed with
  "undeclared", and by the try-body scan that declares such a variable
  `volatile`.
- **A local bound from a unary expression has a type.** The early inference
  pass did not type unary expressions, so after `n = -v` on a lane value,
  `n * 2.0` was a "type mismatch in variable initialization" and `n.x`
  reached the C compiler as a member access on a vector. `-x` and `~x` now
  take x's type there, and `!x` is a bool, as in the type checker.
- **`%` and `~` on float lanes, and `&&`, `||` and `!` on masks, are type
  errors.** They passed the type checker (the logical ones typed as bool)
  and failed in the C compiler. Masks combine with `lanes.mask_and` /
  `mask_or` / `mask_not` and reduce to a bool with `any` / `all`.
- **The lane slice wrappers' bound cannot overflow.** `index + N > buf.len`
  wrapped for an index near the largest long and passed the check; it is
  `index > buf.len - N` now.
- **`docs/api` covers every std module again.** `tools/docgen` held at most
  64 modules and dropped the rest without a word (std has 87), so 29 modules
  had no page and most others were stale: the API pages are regenerated.
  The generator also builds on Windows now (it called the two-argument POSIX
  `mkdir`) and writes LF line endings on every platform.
- **Release PRs no longer run the whole CI matrix twice (#2440).** Since
  changelog fragments, a release PR also deletes the fragments it folds, so
  the `CHANGELOG.md` / `VERSION` skip in `ci.yml`, `windows.yml` and
  `memory-check.yml` never fired: about 32 jobs ran on each release PR and
  again on its merge. `new_changelogs/**` is now in the skip list, and
  `memory-check.yml` cancels a superseded PR run as the other two already
  did.
