- **std.yaml's libfyaml is vendored, and no program links `-lfyaml` any
  more.** A release built against a system libfyaml put `-lfyaml` in
  `ae cflags --libs`, so on a machine without the library every program
  failed to link, hello-world included ("cannot find -lfyaml"). libfyaml
  1.0.0-beta2 now ships in `std/yaml/libfyaml/` (unmodified, pinned by
  SHA-256, regenerated by `scripts/vendor-libfyaml.sh`) and is compiled into
  `libaether.a`, the way std.regex carries PCRE2. `YAML=vendored` is the
  default; `YAML=1` (system library), `YAML=auto` and `YAML=0` (stubs) remain.
  std.yaml now also works in the Windows, FreeBSD and Android releases and in
  `ae build --target` cross builds (not wasi or iOS), which all had the stubs. Every
  vendored symbol is renamed `aether_<name>`, so a program can still link a
  system libfyaml of its own.
