- **`ipc.read_frame_timeout` says whether the stream survived its timeout.** A deadline that passes before the first byte of a frame is `ipc.TIMED_OUT_BETWEEN_FRAMES`: nothing was consumed and the channel is still in step, so a host can send its worker a CANCEL and read the answer. One that passes part-way through a header or payload is `ipc.TIMED_OUT_INSIDE_FRAME`: the bytes read are gone and the channel must be closed. Before, both were "timed out", and a host had to `wait_readable` before every frame to know which it had. The reader still keeps no partial frame between calls.
