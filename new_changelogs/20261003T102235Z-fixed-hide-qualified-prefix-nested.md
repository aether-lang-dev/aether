- **`hide` and `seal except` now hold for qualified names in nested blocks.** `hide fs` blocked `fs.read(...)` only in the block that declared it: one level down (an `if` body, a nested block, a closure) the call compiled, while a hidden bare name was correctly refused at any depth. The qualified check now walks the scope chain as the bare-name lookup does. Separately, `seal except fs` refused every `fs.<member>` call, because the member was then looked up under its mangled name (`fs_exists`), which no whitelist can name; once the prefix passes, the member lookup no longer re-checks hide/seal. Found putting `hide` on sae's page-facing host functions, where nearly every call sits inside an `if`.
