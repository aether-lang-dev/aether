client_pool_configure_raw extern

client_pool_configure_raw(max_idle, max_per_host, idle_ns) -> string

max_idle: int, max_per_host: int, idle_ns: long

HTTP Client — raw ptr-returning externs. These are the escape hatch for code that needs direct access to the underlying HttpResponse struct (e.g. to inspect headers and body together, or to implement custom retry logic). Most callers should use the Go-style wrappers below. Idle connection pool. The client keeps a connection open after a response whose length was definite and reuses it for the next request to the same origin, which is what HTTP/1.1 is designed for: a proxy or a polling client otherwise pays a TCP (and TLS) handshake per request. Reuse is on by default. Connections are keyed by origin, the proxy actually dialled, TLS, and the verification the caller asked for, so a pinned-CA or verification-off connection is never handed to a request that did not ask for it.

client_pool_configure fn

client_pool_configure(max_idle, max_per_host, idle) -> string

max_idle: int, max_per_host: int, idle: Duration

Resize the idle connection pool: how many idle connections to keep in total, how many of those may be to one origin, and how long an unused one is kept before it is closed. The defaults are the call below. http.client_pool_configure(64, 8, 15s) Keep the idle time under the upstream's own keep-alive timeout, or the server closes connections while they sit here and every reuse costs a retry.

client_pool_disable fn

client_pool_disable()

Turn connection reuse off and close what is held. Every request then opens its own connection, which is what the client did before reuse existed.

client_pool_clear fn

client_pool_clear()

Close every idle connection. Useful before measuring, and after a change that makes held connections invalid (a new CA, a rotated proxy).

client_pool_idle_count fn

client_pool_idle_count() -> int

How many idle connections are held right now.

client_rx_buffer_allocs fn

client_rx_buffer_allocs() -> long

How many response buffers the client has had to allocate from nothing, over the life of the process. A pooled connection keeps the buffer its last response was read into and lends it to the next, so a run of requests over one kept connection allocates once, not once per request -- which is what this lets a program, or a test, check rather than assume. Responses whose buffer grew past 64 KiB are not kept, so the idle pool cannot pin an outsized body.

TLS termination (#260 Tier 0). Loads the cert+key (PEM-encoded); after this call every accepted connection completes a TLS handshake before the HTTP parse runs. Returns "" on success, error string otherwise. See server_set_tls below for the Aether-side wrapper.

server_set_tls fn

server_set_tls(server, cert_path, key_path) -> string

server: ptr, cert_path: string, key_path: string

Enable TLS termination on an HTTP server. Both paths must point at PEM-encoded files; the cert and key are validated to match before the server is marked TLS-enabled. Returns "" on success, an error string on failure (file unreadable, parse error, mismatched key, build without OpenSSL). Idempotent — calling twice with the same files is a no-op success; calling with different files re-loads. Example: server = http.server_create(443) err = http.server_set_tls(server, "/etc/ssl/cert.pem", "/etc/ssl/key.pem") if err != "" { println("TLS setup failed: ${err}"); exit(1) } http.server_start(server)

server_set_h2_raw extern

server_set_h2_raw(server, max_concurrent_streams) -> string

server: ptr, max_concurrent_streams: int

HTTP/2 (#260 Tier 2). When enabled: - the TLS context advertises "h2" via ALPN with "http/1.1" as the fallback, so HTTP/2-capable clients (curl --http2, browsers, fan-out gateways) negotiate the framed protocol while older clients stay on HTTP/1.1 transparently; - plain (non-TLS) connections honour h2c upgrade requests per RFC 7540 §3.2 (Upgrade: h2c + HTTP2-Settings header); - per-stream dispatch reuses the existing route table, so all middleware / metrics / access logs / health probes / response transformers (gzip, error_pages) apply uniformly across HTTP/1.1 and HTTP/2 traffic. max_concurrent_streams advertises SETTINGS_MAX_CONCURRENT_STREAMS to the peer. Pass 0 for libnghttp2's default (100). Negative values return an error. Returns "" on success or an error string when the build doesn't link libnghttp2 (the rest of the server keeps working in HTTP/1.1-only mode). Example (h2 over TLS): server = http.server_create(443) err1 = http.server_set_tls(server, "cert.pem", "key.pem") err2 = http.server_set_h2(server, 0) // 0 = nghttp2 default if err1 != "" { println("TLS: ${err1}"); exit(1) } if err2 != "" { println("h2: ${err2}"); exit(1) } http.server_start(server)

server_set_multi_accept_raw extern

server_set_multi_accept_raw(server, on) -> string

server: ptr, on: int

Multi-accept (#3194): in actor dispatch mode, one listener per core (up to 16) on the server's one port, each with SO_REUSEPORT and an accept thread of its own, the kernel spreading connections across them. For connection rates where a single accept() is the bottleneck. `on` is 1 or 0; off by default, and thread-pool mode does not use it. Call it before server_start, after server_bind or without it: a bound socket is kept as the first listener and gives the others its port (a port 0's included), and without one a port 0 is resolved once, so server_port reports the port every listener shares. Returns "" on success, or an error where the kernel does not spread connections across the listeners: it does on Linux and DragonFly (SO_REUSEPORT) and FreeBSD (SO_REUSEPORT_LB), not on Windows, macOS, OpenBSD or NetBSD.

server_monitor_listening_raw extern

server_monitor_listening_raw(server, f)

server: ptr, f: fn

The server's monitor (#3131). The server prints nothing itself: what it has to say goes to closures the program registers before it starts the server. One closure per event, each with typed arguments: http.monitor(srv) { listening() |host: string, port: int| { println("up on ${host}:${port}") } stopped() |host: string, port: int| { metrics_flush() } } `monitor` starts an empty monitor, so an event the block does not name says nothing. The stock monitors are console_monitor (the "Server running at" banner) and null_monitor (silence). With no monitor chosen, server_start, a foreground server, uses console_monitor, and server_start_background, an embedded one, uses none. listening fires once the server accepts connections, and stopped when it stops serving, each on the thread that runs the server: the caller's for server_start, the server's own for server_start_background. Both fire in every dispatch mode, pool or actor. listening comes after the server counts as running, so a server_stop issued from it, or once it has fired, is never lost; a host that must not return from its start until the server serves waits for it. To act on the server from an event, capture it in the closure.

Full SSE event, including `retry:` -- the spec's own reconnection-backoff field (WHATWG HTML, server-sent events). Without it a client can only use its default backoff and the server has no way to say otherwise, so an SSE surface emitting id/event/data but not retry is incomplete rather than merely minimal. 5 of the 20 Datastar cross-SDK conformance goldens require it, which is how the gap surfaced. `retry_ms` <= 0 omits the field; sse_send and sse_send_id pass 0, so their behaviour is unchanged. Field order on the wire is id, event, retry, data -- retry must precede the blank line that dispatches the event.

response_upgrade_sse fn

response_upgrade_sse(res) -> (ptr, string)

res: ptr

Turn an in-flight ordinary response into an SSE stream. `server_sse` registers a whole ROUTE as SSE, which forces the decision before the request is parsed -- so a handler that must be able to answer 400 on a malformed body and only THEN stream cannot use it. This is that seam. Unlike `response_accept_tunnel` this does NOT hand back a raw socket, so it works over TLS: writes go through the connection's own send path. Contract when the handler has already touched `res`: headers set earlier are DISCARDED (the SSE head is fixed, and a stale Content-Length would corrupt the stream), and if a body was already set the upgrade is REFUSED -- that body is data the caller believes it sent. Returns (sse, "") on success, (null, error) when the response is not on a live connection, has already been taken over, or has a body.

ws_connect fn

ws_connect(url) -> ptr

url: string

WebSocket CLIENT: dial a ws:// endpoint and complete the upgrade. The returned handle takes the same verbs as a server-side one -- ws_send_text / ws_recv / ws_message / ws_close -- because the frame codec underneath is shared. The only difference is invisible: RFC 6455 requires a client to mask every frame it sends, and this handle does. Returns null when the URL is malformed, the host is unreachable, the response is not 101, or the Sec-WebSocket-Accept hash does not match the key we sent. That last check matters: without it any 101 would be accepted, including from a server that never saw our handshake. wss:// dials over TLS, reusing the HTTP client's trust store, so the same system CA discovery and TLS floor apply as for https. The peer certificate is verified AND pinned to the host in the URL; a cert with a valid chain but the wrong host is refused. Default port follows the scheme: 80 for ws, 443 for wss. Free with ws_client_free (NOT for server-side handles, which the request loop owns).

ws_recv_timeout fn

ws_recv_timeout(ws, timeout_ms) -> int

ws: ptr, timeout_ms: int

Bounded receive, for a reader that multiplexes many logical streams over one socket and so cannot park a thread in a blocking ws_recv. A WebDriver-BiDi demux is the motivating shape: one reader routes each frame to either an id-keyed pending-reply table or an event queue, and the caller drives the wait with its own event loop. Returns 1 (text), 2 (binary), -1 (closed) exactly as ws_recv, plus 0 for "nothing arrived in time". timeout_ms of 0 polls; negative blocks. The timeout bounds the wait for the START of a frame. Once a frame header has been read the rest of that frame is read to completion, because WebSocket framing is a byte stream with no resynchronisation point -- abandoning a half-read frame would leave the next read treating payload as a header. Pings and continuation frames handled during the wait do not restart the clock, so a chatty peer cannot extend the call indefinitely.

ws_poll fn

ws_poll(ws, timeout_ms) -> int

ws: ptr, timeout_ms: int

Is a frame readable without blocking? 1 = yes, 0 = timed out, -1 = closed/error. Consumes nothing, so a 1 is always followed by a ws_recv that does not block. This asks all three places bytes can be waiting -- the connection's read buffer, the TLS layer's decrypted-but-unread payload, and the socket -- so unlike polling ws_fd yourself it cannot answer "not ready" while a complete frame is already buffered above the socket.

ws_fd fn

ws_fd(ws) -> int

ws: ptr

The underlying socket, for a native event loop (asyncio.add_reader, epoll, kqueue). Returns -1 when closed. CONTRACT -- read this before using it. The descriptor is a readiness HINT, not an authority: a frame can sit in the connection buffer, or decrypted inside the TLS layer, with nothing pending on the socket. An event loop that waits on this fd alone will eventually miss a frame that has already arrived, and then block. The safe pattern is: when your event loop reports the fd readable, drain it dry: draining = 1 while draining == 1 { k = http.ws_recv_timeout(ws, 0) // never blocks if k == 0 { draining = 0 } // nothing left; go back to waiting if k > 0 { route(k) } if k < 0 { draining = 0 } // peer gone } i.e. treat readability as "go look", and let ws_recv_timeout(ws, 0) be the authority on whether a frame is actually there. If you want one call that answers authoritatively, use ws_poll instead.

request_body_read fn

request_body_read(req, offset, max) -> (string, int, string)

req: ptr, offset: int, max: int

Chunked-read access to the request body (#626). Reads up to `max` bytes from `offset` into an owned AetherString. Returns (bytes, n, "") on success — `n` may be less than `max` at EOF. Returns ("", 0, error) on failure. RAM-bounded for large uploads (#626). A body larger than the 16 KiB connection buffer is NOT buffered whole: the server parses headers, then this accessor pulls each window straight off the socket. Reads must be sequential (offset advances by the returned `n`, which the loop below does naturally). Small bodies stay fully buffered and support random-access offsets. Either way the loop below is identical — peak server memory for a large PUT is one window per connection, not the whole object. Pair with `request_body_length` to drive the loop: total = http.request_body_length(req) off = 0 while off < total { chunk, n, err = http.request_body_read(req, off, 65536) if err != "" { ...handle... break } if n == 0 { break } fs.pwrite(out_file, string.bytes(chunk)[0..n], off) // stream to disk off = off + n }

request_body_complete fn

request_body_complete(req) -> int

req: ptr

#644: has the request body fully arrived? 1 once every declared byte has been received (streaming request: pulled off the wire by request_body_read / request_body; buffered request: always 1). The natural loop terminator for chunked iteration: off = 0 while http.request_body_complete(req) == 0 { chunk, n, err = http.request_body_read(req, off, 65536) if err != "" { ...handle... break } if n == 0 { break } ...consume chunk... off = off + n }
