ipc

std.ipc — a process's channel to its parent: a report pipe, or a two-way socket that can also pass open file descriptors.

import std.ipc

parent_channel_raw extern

parent_channel_raw() -> int

Returns the parent-channel fd if the parent spawned this process via os.run_pipe or os.run_socket (i.e. AETHER_IPC_FD is set in env and the named fd is open); -1 otherwise. Children of os.run / os.run_capture see -1 — those don't open a back-channel. On Windows always -1 (v1 stub). The fd value is whatever the parent picked; current parent-side default is 3 but consumers MUST NOT hardcode that.

parent_channel fn

parent_channel() -> int

Aether-side wrappers. parent_channel returns the raw int from the extern; -1 sentinel for "no parent channel."

parent_channel_kind fn

parent_channel_kind() -> string

"socket" for a channel from os.run_socket (two-way, can pass descriptors), "pipe" for one from os.run_pipe (write-only from the child), "stdio" in a child of os.run_stdio (AETHER_IPC_KIND=stdio in its environment; parent_channel() is -1 there, the channel being stdin and stdout: claim it with stdio_channel()), "" otherwise.

stdio_channel fn

stdio_channel() -> (int, int, string)

Claim this process's stdin and stdout as a channel, for a child that os.run_stdio (or anything else that hands it two pipes as stdin and stdout, such as a container runtime run with -i) talks frames to. Call it first thing in main. Returns (in_fd, out_fd, "") on success: read frames from in_fd, write them to out_fd. (-1, -1, err) on failure, with nothing changed; a second call is "ipc.stdio_channel: already claimed". It flushes stdout, moves fd 0 and fd 1 to two new close-on-exec descriptors (non-inheritable handles on Windows), the channel, then points fd 0 at the null device (/dev/null, NUL), so nothing else reads the channel's bytes (a read of stdin gets end of file at once), and fd 1 at stderr (the null device when there is none), so a later print, println, library diagnostic or panic message lands on stderr instead of in the middle of a frame. On Windows the Win32 standard handles are pointed the same way (SetStdHandle), so writers that use GetStdHandle follow too. AETHER_IPC_KIND is cleared, so the children of this process do not think they are on a channel. What it cannot mask: anything written to stdout before the call (flushed out ahead of the first frame: a child must print nothing first), bytes C stdio read ahead from stdin before the call (lost), and code that holds its own copy of fd 1 or of the old stdout handle, such as a descriptor dup'd before the call or a child process started before it, which still writes into the channel. It works whether or not os.run_stdio set AETHER_IPC_KIND (a container runtime does not pass it through).

write fn

write(fd, bytes) -> string

fd: int, bytes: string

Write all of `bytes` to `fd`. Returns "" on success, non-empty error string on failure. A short write continues where it stopped and an interrupted one retries, so "" means every byte went; a string with a zero byte in it goes whole. On a socket or a pipe whose peer has gone this is an error, not SIGPIPE. For the common case where the child writes one payload and exits, prefer write_close so the parent's read_all loop sees EOF promptly.

write_close fn

write_close(fd, bytes) -> string

fd: int, bytes: string

Write `bytes` then close the channel. The common case: child produces one structured report at exit and closes the fd so the parent's drain loop sees EOF and stops. Calling close releases the writer's reference on the pipe; the parent sees EOF only after every writer has closed. If the child is itself going to exit immediately after, the kernel will close the fd anyway during process teardown — explicit close is still preferred because it lets the parent's reader unblock before the child exits, useful when the parent's reader runs in the same thread as the child-wait loop.

read fn

read(ch, max) -> (string, string)

ch: int, max: int

One read of up to `max` bytes: (data, "") with what arrived, which may be less than was written (the channel is a byte stream; framing is the caller's), ("", "") at end of stream, or ("", err). Binary-safe. Blocks until something arrives.

send_fd fn

send_fd(ch, fd, payload) -> string

ch: int, fd: int, payload: string

Pass the open descriptor `fd` to the process at the other end of socket `ch`, attached to `payload`, which must be at least one byte (on a stream socket a descriptor travels with bytes). The receiver gets its own descriptor for the same open file; this side's `fd` stays open, so close it when this side is done with it.

recv_fd fn

recv_fd(ch, max) -> (int, string, string)

ch: int, max: int

Receive one descriptor from socket `ch`, with the bytes that came with it (up to `max`): (fd, payload, ""), or (-1, "", err). The descriptor is close-on-exec. A message carrying no descriptor, more than one, or control data of another kind is an error, and every descriptor that did arrive is closed first.

recv fn

recv(ch, max) -> (string, int, string)

ch: int, max: int

One receive from socket `ch`: (data, fd, ""), up to `max` bytes and the descriptor that came with them, or -1 when the message carried none. One recvmsg returns both, so a peer need not announce a descriptor before sending it. ("", -1, "") is end of stream; ("", -1, err) a failure. At most one descriptor (close-on-exec). More than one, control data of another kind, or control data cut short is an error, and every descriptor that arrived is closed first, with the bytes that came with it. The parent end of a channel os.run_socket made takes no descriptor at all: one arriving from the child is closed and an error returned, with no opt-in by the host (a sandboxed child has no business handing its parent descriptors). The child end and os.socketpair's ends accept. The parent end is the descriptor os.run_socket returned, until it is closed with io.fd_close; recv_fd refuses on it too. read, which receives no control data, lets the kernel drop a descriptor riding on the bytes.

write_frame fn

write_frame(ch, data) -> string

ch: int, data: string

Write `data` as one frame: a 4-byte big-endian unsigned length, then the bytes. Any bytes, 0x00 and 0x0a included: the length is the string's, not a terminator's. "" or an error; a payload of 4 GiB or more is one. An empty payload is a frame of length 0.

read_frame fn

read_frame(ch, max) -> (string, string)

ch: int, max: int

Read one frame: (data, "") whole, blocking until all of it has arrived. `max` is a hard cap on the payload: a header announcing more is an error, and nothing is allocated or read past the header. A frame split at any offset across writes reads the same. Exactly the frame is consumed, never a byte of the next. A frame of length 0 is ("", ""). End of stream before the first header byte is the error "end of stream", so ("", "") is never an end; end inside a frame is an error too. Receives no descriptors (see recv).

read_frame_timeout fn

read_frame_timeout(ch, max, timeout_ms) -> (string, string)

ch: int, max: int, timeout_ms: int

read_frame with a deadline: `timeout_ms` bounds the whole frame, header and payload together, so a peer that sends a header and stalls, or drips bytes, cannot hold the reader past it. A negative timeout waits forever, as read_frame does. A timeout is one of two errors: TIMED_OUT_BETWEEN_FRAMES when no byte of a frame had arrived (the stream is intact; carry on using it), TIMED_OUT_INSIDE_FRAME when one had (close the channel). Any other error leaves the stream unusable too. On Windows the channel must be an anonymous pipe, such as os.run_stdio's (any other descriptor is a "not a pipe" error, unless the timeout is negative), and the deadline is kept to within about a timer tick (~16 ms).

wait_readable fn

wait_readable(ch, timeout_ms) -> (int, string)

ch: int, timeout_ms: int

Wait up to `timeout_ms` for `ch` to be readable (poll): (1, "") when a read will not block, which includes the peer having closed (the read then gives end of stream), (0, "") on a timeout, (0, err) on a failure. A negative timeout waits forever; 0 asks without waiting. Bounds the wait for the first byte of read or recv. Frames need no wait first: read_frame_timeout tells a timeout between frames from one inside a frame. On Windows only an anonymous pipe, such as os.run_stdio's from_child_fd, can be waited on (any other descriptor is a "not a pipe" error); a peer that has closed reads as ready there too. It polls the pipe, so bytes and the deadline are noticed within about a timer tick (~16 ms); 0 asks once without sleeping.

wait_writable fn

wait_writable(ch, timeout_ms) -> (int, string)

ch: int, timeout_ms: int

Wait up to `timeout_ms` for room to write on `ch` (poll for POLLOUT): (1, "") when a write_some will take bytes, which includes the reader having gone (the write then says so), (0, "") on a timeout, (0, err) on a failure. A negative timeout waits forever; 0 asks without waiting. On a pipe, room means at least PIPE_BUF bytes (512 on macOS and the BSDs, 4096 on Linux): a plain write of more can still wait, so write with write_some or a frame writer. On Windows an anonymous pipe has no readiness to poll: this asks the pipe how many bytes it holds free (WriteQuotaAvailable), a timer tick apart (~16 ms). Windows counts a reader's waiting read against that room, so a reader blocked in a read as large as the pipe's buffer (4096 bytes for os.run_stdio's pipes) makes an empty pipe look full: wait_writable times out there although a write would go. A frame writer does not depend on it. A file or a console is always ready; another descriptor is a "not a pipe" error.

write_some fn

write_some(fd, bytes, offset) -> (int, string)

fd: int, bytes: string, offset: int

Write the bytes of `bytes` from `offset` on that `fd` takes now, and return without waiting for the rest: (n, "") with n the count written, which may be 0 (the pipe or socket is full) or anything up to the rest; (n, err) when a write failed after n bytes, the reader having gone included (an error, not SIGPIPE). Call it again with offset + n when there is room (wait_writable). Binary-safe; nothing is copied. It does not change the descriptor's flags. On POSIX a socket is sent to with MSG_DONTWAIT; a pipe is written PIPE_BUF bytes at a time while poll says there is room, which a blocking write of that size never waits for; a descriptor already non-blocking is written straight. On Windows a pipe is written no more than its free room (WriteQuotaAvailable), which never waits; when it reports none and holds no bytes (a reader waiting in a large read), the pipe is put in PIPE_NOWAIT mode for this call's writes and back in PIPE_WAIT before it returns. A file or a console is written whole. Do not write the same descriptor from another thread at the same time.

frame_writer fn

frame_writer(fd) -> ptr

fd: int

A frame writer on `fd`: frames are queued (frame_writer_put) and written as the reader takes them (frame_writer_flush), so a thread that must not wait on a reader, a UI thread, writes frames without a thread of its own. A frame cut short by a full pipe goes on where it stopped at the next flush, so the reader gets whole frames, in order. Each writer has its own queue; the descriptor stays the caller's to close (frame_writer_free does not close it). null when `fd` is negative or memory ran out. Use it from one thread at a time, and do not write to `fd` around it.

frame_writer_put fn

frame_writer_put(w, data) -> string

w: ptr, data: string

Queue `data` as one frame (the bytes write_frame would write); nothing is written. "" or an error (a payload of 4 GiB or more, out of memory).

frame_writer_flush fn

frame_writer_flush(w, timeout_ms) -> string

w: ptr, timeout_ms: int

Write what is queued, waiting for room at most `timeout_ms` in all: 0 writes what the descriptor takes now and never waits, a negative timeout waits until all of it is written. "" when it was all written or the time ran out (frame_writer_pending says which), or the error that stopped it, such as the reader having gone; what was not written stays queued. A peer that takes nothing for long enough is the caller's to give up on (close the descriptor, free the writer).

frame_writer_pending fn

frame_writer_pending(w) -> long

w: ptr

How many queued bytes are not written yet (frame headers included).

frame_writer_free fn

frame_writer_free(w)

w: ptr

Free a frame writer and what it still has queued. The descriptor is not closed.

TIMED_OUT_BETWEEN_FRAMES const

TIMED_OUT_BETWEEN_FRAMES = "ipc.read_frame: timed out before a frame began"

read_frame_timeout's error when the deadline passed before the first byte of a frame arrived. Nothing was consumed: the stream is between frames and fit to use, to send the peer a CANCEL, say, and read its answer.

TIMED_OUT_INSIDE_FRAME const

TIMED_OUT_INSIDE_FRAME = "ipc.read_frame: timed out inside a frame; the stream is out of step"

read_frame_timeout's error when the deadline passed part-way through a frame's header or payload. The bytes already read are gone with the call, so the stream is out of step: close the channel.
