connect fn

connect(host, port) -> (ptr, string)

host: string, port: int

Connect to host:port. Returns (socket, "") on success, (null, error) on failure. Caller must tcp.close the returned socket.

write fn

write(sock, data) -> (int, string)

sock: ptr, data: string

Write data to a socket. Returns (bytes_sent, "") on success, (0, error) on failure. Note: named `write`/`read` (not `send`/`receive`) because `send` and `receive` are reserved actor keywords in Aether. The `tcp.send_raw` extern is still available under the old name for direct use.

write_n fn

write_n(sock, data)

sock: ptr, data: byte[]

Length-aware socket write: sends the bytes of `data`, whose length travels with the slice (#2301), so embedded NUL bytes do not truncate the send. Returns the OS send(2) byte count; callers that require full-buffer delivery should loop, sending `data[n..]` until every byte has been accepted. An empty slice sends nothing and returns (0, ""). For a string, send its byte view: `tcp.write_n(sock, string.bytes(s))`, a prefix with `string.bytes(s)[0..n]`; for a `std.bytes` buffer, `bytes.view(buf)`.

write_slice fn

write_slice(sock, s) -> (int, string)

sock: ptr, s: byte[]

Write a `byte[]` slice's bytes, binary-safe: the length travels with the slice (#2301). Returns (bytes_sent, "") or (0, "send failed"). The count is one send(2) and may be SHORT, as with write_n: a caller that needs the whole slice delivered loops on the rest, `s[sent..]`. An empty slice sends nothing and returns (0, ""). A slice with no bound panics.

read fn

read(sock, max_bytes) -> (string, string)

sock: ptr, max_bytes: int

Read up to max_bytes from a socket. Returns (data, "") on success, ("", error) on transport failure or connection close. This text wrapper copies with string_concat and is strlen-shaped; use read_n when the payload may contain embedded NUL bytes.

read_n fn

read_n(sock, max_bytes) -> (string, int, string)

sock: ptr, max_bytes: int

Binary-safe read. Returns (bytes, length, "") on success, with the byte buffer stored in a length-aware AetherString. The returned length is authoritative; callers should pass it to length-aware consumers rather than re-derive length with strlen-shaped APIs. Error discipline (#1092): a quiet-but-alive peer (recv-timeout / would-block) returns ("", 0, "timeout") and leaves the socket connected — retry or poll, do NOT treat it as a close. Only an orderly FIN or a hard error returns "connection closed or receive failed"; that is the terminal state. A full-duplex relay must branch on the "timeout" sentinel rather than collapsing all non-empty errors into "closed."

read_into fn

read_into(sock, buf) -> (int, string)

sock: ptr, buf: byte[]

Read into a caller-owned `byte[]` (#2301): one receive of at most `buf.len` bytes, nothing allocated, never a byte past `buf.len`. Returns (n, "") with the data in `buf[0..n]`, which may be fewer bytes than asked. Errors follow read_n: (0, "timeout") for a quiet peer (the socket stays connected: retry or poll), (0, "connection closed or receive failed") for an orderly close or an error (terminal). An empty slice returns (0, "receive buffer is empty") without touching the socket; a slice with no bound panics.

listen fn

listen(port) -> (ptr, string)

port: int

Listen on a port. Returns (server, "") on success, (null, error) on failure. Caller must tcp.server_close the returned server.

listen_on fn

listen_on(address, port) -> (ptr, string)

address: string, port: int

Listen on ONE address (#2136): "127.0.0.1" for a loopback-only channel that the network cannot reach, "0.0.0.0" for every interface (what `listen` does). Port 0 asks the OS for an ephemeral port; read it back with `server_port`. Returns (server, "") or (null, error).

accept fn

accept(server) -> (ptr, string)

server: ptr

Accept an incoming connection. Returns (socket, "") on success, (null, error) on failure or shutdown.

fd fn

fd(sock) -> int

sock: ptr

The OS-level descriptor inside a connected socket, or -1 if the handle is null/closed (#1003). Exists for capability plumbing: connect through the stdlib, then narrow the descriptor with capsicum.rights_limit(tcp.fd(sock), ...) before capsicum.enter(). The fd is owned by the handle — do not close it directly; it is released by tcp.close.

server_fd fn

server_fd(server) -> int

server: ptr

The OS-level listening descriptor inside a server handle, or -1 if the handle is null (#1003). Same ownership rule: released by tcp.server_close, never closed directly.

server_port fn

server_port(server) -> int

server: ptr

The port a server is bound to — the one the OS chose for a `listen_on(addr, 0)` — or -1 for a null handle.

server_poll fn

server_poll(server, timeout_ms) -> int

server: ptr, timeout_ms: int

Wait up to timeout_ms for a connection to be waiting, so `accept` will not block: 1 = a connection is queued, 0 = timeout, -1 = null handle or error. A serving loop with a stop flag polls this between checks of the flag instead of blocking in `accept` (closing the listener from another thread does not wake `accept` on Linux).

set_nodelay fn

set_nodelay(sock, on) -> string

sock: ptr, on: bool

TCP_NODELAY: send each write at once instead of waiting to coalesce it (Nagle). Request/response lines want it on. Returns "" on success or an error; `setsockopt` cannot be declared from Aether because the runtime's headers already declare it with the platform's signature.

poll fn

poll(sock, timeout_ms) -> (_0, string)

sock: ptr, timeout_ms: int

Wait until `sock` is readable, up to timeout_ms (-1 blocks, 0 polls, >0 waits that many ms). Returns (true, "") when a subsequent read_n will not block, (false, "") on timeout, (false, error) if the handle is closed or poll failed. Neither reads nor closes the socket — pair it with read_n to build a nonblocking loop over a single direction.

poll2 fn

poll2(a, b, timeout_ms) -> (_0, _1, string)

a: ptr, b: ptr, timeout_ms: int

Wait on two sockets at once — the full-duplex relay primitive. Returns (a_ready, b_ready, "") where each flag is true when that side is readable (both may be true); (false, false, "") on timeout; (false, false, error) if both handles are closed or poll failed. Service whichever side is ready with read_n, then re-poll.
