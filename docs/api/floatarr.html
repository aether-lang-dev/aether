floatarr

std.floatarr - Fixed-size packed-double buffer (float twin of std.intarr) For SVG path-command args, rasterizer edge tables, bbox accumulators, blur kernel coefficients, and other hot paths where std.list's void*-boxed items cost an allocation per entry.

import std.floatarr

new fn

new(size) -> (ptr, string)

size: int

Allocate a FloatArray of `size` elements, zero-initialised. Returns (ptr, "") on success, (null, error) on failure.

new_filled fn

new_filled(size, init) -> (ptr, string)

size: int, init: float

Allocate and fill with `init` at every index.

get fn

get(arr, i) -> (float, string)

arr: ptr, i: int

Bounds-checked read. Returns (value, "") on success, (0.0, error) for null array or OOB index. Use the raw `floatarr_get_raw` directly (imported above) when you don't need to tell absent apart from stored-zero — it's one fewer function call and one fewer branch.

set fn

set(arr, i, value) -> string

arr: ptr, i: int, value: float

Bounds-checked write. Returns "" on success, error for null array or OOB index. Use the raw `floatarr_set_raw` directly in hot paths where a no-op-on-OOB is acceptable.

get_raw extern

Read at `i`. Returns 0.0 if `arr` is null or `i` is out-of-range. Use `floatarr.get` (below) to distinguish stored-zero from OOB.

Write `value` at `i`. No-op if `arr` is null or `i` is out-of-range. Use `floatarr.set` (below) if you need an error on OOB.

data extern

Hot-path variants — caller guarantees index is in [0, size). OOB access is undefined behaviour. Don't use from outside a tight loop.

array fn

array(arr) -> float[]

arr: ptr

array(arr) -- the buffer as a plain `float[]`, so `v[i]` works (#2041). `a[i]` on the HANDLE cannot work: the handle is a bare `ptr`, and `[]` has no element type to dispatch on. A view is typed, so it does: v = floatarr.array(a) v[3] = 1.5 total = total + v[3] and the compiler lowers `v[i]` to the same load `floatarr_get_unchecked` inlines to, so the readable spelling costs nothing. `std.strarr` has had this shape since it was written. The view is bounded by the array's size (#2301): `v.len` is `floatarr.size(a)` and `v[i]` outside it is the slice bounds panic, not a read past the buffer. Pass it to std.sort (`sort.floats(v)`), or any `float[]` parameter, whole or as a sub-slice. A null handle is the empty slice. BORROWED, not owned: valid until the handle is freed. For the unchecked load in a hot loop, `floatarr_get_unchecked` is still there.
