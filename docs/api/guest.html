guest

std.guest: an Aether host running a guest in a separate, sandboxed child process, and talking to it both ways over std.ipc.

import std.guest

Guest struct

struct Guest

A running guest. `deadline_ms`, `grace_ms` and `max_frame` may be changed at any time.

Event struct

struct Event

One thing the guest did. kind is SAY text LOG code = the level 0..5, name = TRACE .. FATAL, text = the message, tags = a JSON object; nothing to answer CALL name, text = the arguments as a JSON array; answer it with answer, fail, grant_file or deny before the next call to next DONE code, the script's exit code ERROR text, the guest's message ("cancelled by host: ..." after a deadline or a cancel) KILLED text, why the host hung up and killed it READY text = the exported names as a JSON array (also g.exported): the script has ended and the guest serves; invoke, or end RETURN text = the JSON value the invoked function returned RAISE text = the error the invoked function raised; the guest still serves IDLE next was called while the guest serves: nothing was read

launch fn

launch(perms, prog, args, name, audit_path) -> (Guest, string)

perms: sandbox.Grants, prog: string, args: ptr, name: string, audit_path: string

Starts the worker program `prog` in a child held to `perms` (sandbox.spawn_socket), with `args`, a std.list of strings, as its arguments (null for none: an Aether worker reads everything from the socket; a foreign interpreter takes its script, `-I guest.py`). Fails closed: where the child cannot be contained (macOS, Windows; Linux without Landlock) it returns the reason and starts nothing. `name` labels the audit log lines; `audit_path` is the log ("" for none). An Aether worker needs no grants to run a script: it is one binary and reads its script from the socket.

launch_uncontained fn

launch_uncontained(perms, prog, args, name, audit_path) -> (Guest, string)

perms: sandbox.Grants, prog: string, args: ptr, name: string, audit_path: string

launch with NO process sandbox (sandbox.spawn_socket_uncontained), for development where spawn_socket refuses (macOS). The worker still locks itself down with sandbox.enforce. The audit log says which it was.

mount fn

mount(g, name, min, max) -> string

g: *Guest, name: string, min: int, max: int

Mounts a host function `name` taking min..max arguments. Before start.

probe fn

probe(g) -> string

g: *Guest

Asks the guest to check its own wall once it has locked down: it tries to read /etc/passwd and connect to 1.1.1.1:443 and reports both as AUDIT lines. Before start.

log_level fn

log_level(g, level) -> string

g: *Guest, level: int

Sets the guest's log threshold: -1 off (the default), 0 trace, 1 debug, 2 info, 3 warn, 4 error, 5 fatal. Before start it holds from the first step; after, from the guest's next step, also while a CALL waits for its answer. Out of range: the error, and nothing is sent.

start fn

start(g, source) -> string

g: *Guest, source: string

Sends the script; the guest locks itself down and runs it. A max_frame set below MAX_FRAME goes first, as MAXFRAME, so the worker holds what it sends to the limit this host will read: a RETURN it cannot send whole it can RAISE instead (std.guest.child, returned). At the default nothing extra is sent. A max_frame lowered after start the worker does not hear of: its frames over it are refused here, and the guest killed.

answer fn

answer(g, json) -> string

g: *Guest, json: string

Answers the pending CALL with a JSON value.

fail fn

fail(g, why) -> string

g: *Guest, why: string

Fails the pending CALL; the script sees an error with this message.

grant_file fn

grant_file(g, name, path) -> string

g: *Guest, name: string, path: string

Answers the pending CALL, a request for the file `name`, with the file at `path` as an open descriptor: the guest reads it and the script gets {"granted":true,"text":...}. If `path` cannot be opened it is a deny.

deny fn

deny(g, name, why) -> string

g: *Guest, name: string, why: string

Answers the pending CALL, a request for the file `name`, with no: the script gets {"granted":false,"why":why}.

cancel fn

cancel(g, reason) -> string

g: *Guest, reason: string

Asks the guest to stop now: its script, its invocation, or (serving) itself. next() then returns its ERROR. A cancel ends the guest (cancelling, below).

next fn

next(g) -> Event

g: *Guest

The guest's next event, waiting at most deadline_ms for it (see the top of this file). AUDIT frames go to the audit log and are not returned.

close fn

close(g)

g: *Guest

Ends a guest early: hangs up and kills it. Safe after it has finished.

audit fn

audit(&g, "SPAWN refused)

&g, "SPAWN refused: ${err}"

invoke fn

invoke(g, name, args) -> string

g: *Guest, name: string, args: string

Calls the guest's exported function `name` with `args`, a JSON array. Only while the guest serves: after READY, and after the RETURN or RAISE that ended the last invocation. The host then reads the invocation's events with next as it reads a script's: SAY, LOG, CALL (answer each), and at the end RETURN or RAISE, each exchange bounded by deadline_ms. A deadline that passes cancels the guest, which ends it. "" when sent, or why nothing was: the guest is not serving (its script, an invocation or a host call it waits on is still running, or it is ending), it does not export `name`, `args` is not an array, or the INVOKE frame would be longer than MAX_FRAME, the most a worker reads. A frame the idle guest sent unasked is a protocol error: the host hangs up and says so.

end fn

end(g) -> string

g: *Guest

Ends a serving guest politely: END, which it answers with DONE 0 (next returns it, and reaps the guest). "" or why nothing was sent.

result fn

result(e) -> (string, string)

e: Event

An invocation's outcome from the event that ended it: (the JSON value, "") for RETURN; ("", the error) for RAISE, and for the ERROR, KILLED or DONE that ended the guest instead.

is_exported fn

is_exported(g, name) -> bool

g: *Guest, name: string

Whether the guest's READY exported `name` (compared exactly).

is_serving fn

is_serving(g) -> bool

g: *Guest

Whether the guest is idle and serving: invoke and end may be called.

run_script fn

run_script(g, source, on_event) -> Event

g: *Guest, source: string, on_event: fn

Starts `source` and runs it to its end, handing every SAY, LOG and CALL to `on_event`, a function of (*Guest, Event), which answers each CALL (answer, fail, grant_file or deny). A CALL it leaves unanswered is failed for it. Returns the event that ended the script: READY (the guest serves; call_export, then end), DONE, ERROR or KILLED.

call_export fn

call_export(g, name, args, on_event) -> (string, string)

g: *Guest, name: string, args: string, on_event: fn

invoke, then the invocation's events up to its end, handed to `on_event` as run_script hands a script's: (the JSON value, "") for a RETURN; ("", the error) for a RAISE, a refused invoke, or the end of the guest (a deadline, a kill). The guest still serves after a RAISE.

json_string fn

json_string(s) -> string

s: string

`s` as a JSON string literal.

printable fn

printable(s) -> string

s: string

`s` safe to print or log: control bytes, DEL and backslashes as \xNN, so a guest cannot forge a log line or send escape sequences to a terminal.

level_name fn

level_name(level) -> string

level: int

TRACE, DEBUG, INFO, WARN, ERROR or FATAL for a level 0..5; "?" otherwise.

MAX_EXPORT_NAME const

SCRIPT const

SCRIPT = 0

Where a guest's conversation is (Guest.phase): SCRIPT its script runs (from launch to READY or DONE) SERVING its script has ended with READY: idle, waiting for INVOKE or END INVOKING an invocation runs (from INVOKE to RETURN or RAISE) ENDING END has been sent: only DONE (or ERROR) may come CANCELLED CANCEL has been sent: the guest is ending (see cancelling)
