guest

std.guest: an Aether host running a guest in a separate, sandboxed child process, and talking to it both ways over std.ipc.

import std.guest

Guest struct

struct Guest

A running guest. `deadline_ms`, `grace_ms` and `max_frame` may be changed at any time.

Event struct

struct Event

One thing the guest did. kind is SAY text LOG code = the level 0..5, name = TRACE .. FATAL, text = the message, tags = a JSON object; nothing to answer CALL name, text = the arguments as a JSON array; answer it with answer, fail, grant_file or deny before the next call to next DONE code, the script's exit code ERROR text, the guest's message ("cancelled by host: ..." after a deadline or a cancel) KILLED text, why the host hung up and killed it

launch fn

launch(perms, prog, args, name, audit_path) -> (Guest, string)

perms: sandbox.Grants, prog: string, args: ptr, name: string, audit_path: string

Starts the worker program `prog` in a child held to `perms` (sandbox.spawn_socket), with `args`, a std.list of strings, as its arguments (null for none: an Aether worker reads everything from the socket; a foreign interpreter takes its script, `-I guest.py`). Fails closed: where the child cannot be contained (macOS, Windows; Linux without Landlock) it returns the reason and starts nothing. `name` labels the audit log lines; `audit_path` is the log ("" for none). An Aether worker needs no grants to run a script: it is one binary and reads its script from the socket.

launch_uncontained fn

launch_uncontained(perms, prog, args, name, audit_path) -> (Guest, string)

perms: sandbox.Grants, prog: string, args: ptr, name: string, audit_path: string

launch with NO process sandbox (sandbox.spawn_socket_uncontained), for development where spawn_socket refuses (macOS). The worker still locks itself down with sandbox.enforce. The audit log says which it was.

mount fn

mount(g, name, min, max) -> string

g: *Guest, name: string, min: int, max: int

Mounts a host function `name` taking min..max arguments. Before start.

probe fn

probe(g) -> string

g: *Guest

Asks the guest to check its own wall once it has locked down: it tries to read /etc/passwd and connect to 1.1.1.1:443 and reports both as AUDIT lines. Before start.

log_level fn

log_level(g, level) -> string

g: *Guest, level: int

Sets the guest's log threshold: -1 off (the default), 0 trace, 1 debug, 2 info, 3 warn, 4 error, 5 fatal. Before start it holds from the first step; after, from the guest's next step, also while a CALL waits for its answer. Out of range: the error, and nothing is sent.

start fn

start(g, source) -> string

g: *Guest, source: string

Sends the script; the guest locks itself down and runs it.

answer fn

answer(g, json) -> string

g: *Guest, json: string

Answers the pending CALL with a JSON value.

fail fn

fail(g, why) -> string

g: *Guest, why: string

Fails the pending CALL; the script sees an error with this message.

grant_file fn

grant_file(g, name, path) -> string

g: *Guest, name: string, path: string

Answers the pending CALL, a request for the file `name`, with the file at `path` as an open descriptor: the guest reads it and the script gets {"granted":true,"text":...}. If `path` cannot be opened it is a deny.

deny fn

deny(g, name, why) -> string

g: *Guest, name: string, why: string

Answers the pending CALL, a request for the file `name`, with no: the script gets {"granted":false,"why":why}.

cancel fn

cancel(g, reason) -> string

g: *Guest, reason: string

Asks the guest to stop its script now. next() then returns its ERROR.

next fn

next(g) -> Event

g: *Guest

The guest's next event, waiting at most deadline_ms for it (see the top of this file). AUDIT frames go to the audit log and are not returned.

close fn

close(g)

g: *Guest

Ends a guest early: hangs up and kills it. Safe after it has finished.

audit fn

audit(&g, "SPAWN refused)

&g, "SPAWN refused: ${err}"

json_string fn

json_string(s) -> string

s: string

`s` as a JSON string literal.

printable fn

printable(s) -> string

s: string

`s` safe to print or log: control bytes, DEL and backslashes as \xNN, so a guest cannot forge a log line or send escape sequences to a terminal.

level_name fn

level_name(level) -> string

level: int

TRACE, DEBUG, INFO, WARN, ERROR or FATAL for a level 0..5; "?" otherwise.
