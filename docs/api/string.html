retain extern

retain(str)

str: string

Reference counting. `str` is `@retain` on every refcount call: each one takes ownership of the lifetime decision (release decrements + frees at refcount 0; retain bumps the refcount; free drops the allocation immediately). The escape walker marks any heap- string variable passed at this slot as escaped, so the function-exit defer-free does not also call free() on the same buffer, without `@retain` here, a `defer string.release(s)` paired with the auto-cleanup would double-free the underlying allocation. After the call the caller's `_heap_<name>` tracker is conservatively kept at its previous value; the var is treated as dead from the reclamation system's perspective. These free what the runtime can SEE is heap: a value carrying the AetherString magic header. A plain malloc'd payload is indistinguishable from a literal here and is left alone, so producing one and handing it to a caller to free would leak it. That is why the uniform-heap return wrap mints the refcounted shape rather than a bare buffer.

concat_wrapped extern

concat_wrapped(a, b) -> string

a: string, b: string

Length-bearing concat. Returns a refcounted AetherString; downstream string.length() honours the stored length rather than falling through to strlen() and silently truncating at the first NUL. Use when joining inputs that may contain binary bytes (base64-decoded payloads, fs.read_binary output, …). Issue #270. Returns `string`: the C function yields an owned, refcounted AetherString*, which is exactly the magic `string` representation. Typing it `string` (not `ptr`) lets the codegen track the result as an owned heap string and release it at scope exit, and unwrap it to its payload bytes at naive-C-extern boundaries (#297). The C ABI is unchanged — the header still declares `AetherString*`.

substring_n extern

substring_n(str, str_len_bytes, start, end) -> string

Length-aware sibling — caller supplies the source length explicitly. Reach for this when `str` arrives as a `string` parameter at a function boundary (where #297's auto-unwrap may have stripped the AetherString header) AND the content may contain embedded NULs. The plain string_substring would call str_len() on the unwrapped data and fall through to strlen, truncating at the first NUL. split extern

split(str, delimiter) -> ptr

str: string, delimiter: string

String array operations. LIFETIME WARNING — `string_array_get` returns a *borrowed* pointer into the array's internal storage, NOT an owned copy. After `string_array_free(arr)` every pointer previously handed out by `string_array_get(arr, ...)` is dangling. The natural-looking pattern below silently use-after-frees: v = string.array_get(parts, idx) string.array_free(parts) return v // <- v dangles Symptom is garbage bytes / random crashes downstream — the array's backing storage is gone but the pointer still reads. Safe options when you need a value to outlive the array: 1. Copy first: v = string.concat(string.array_get(parts, idx), "") then string.array_free(parts) — the concat made an owned, refcounted copy. 2. Use `string_split_to_seq` (declared further down) — returns a refcounted `*StringSeq` whose cells own their data independently of any backing array, so there's no array-wide free to worry about. This is the RECOMMENDED shape: a `*StringSeq` local is reclaimed DETERMINISTICALLY by the compiler — freed automatically at scope exit via the refcount-decrementing `string_seq_free`, the same way heap strings are. No manual free, and (because the free is a decrement) structurally-shared tails stay safe. A piece you pull from a sequence and let escape transfers ownership cleanly, with no dangling-into-a-backing-array hazard. If your access pattern is "build, walk once, free" within a single scope, the borrowed-pointer form is fine and the cheapest. Reach for option 1/2 only when a piece needs to escape the array's lifetime.

join extern

join(seq, sep) -> string

seq: *StringSeq, sep: string

Join a sequence into one string with `sep` between elements — the linear-cost complement to string_split (issue #1346). O(total bytes): one pass to size the result, one allocation, one pass to copy. Empty sequence → "". The natural pair for `string_split` / `string_split_to_seq`: parts = string.split_to_seq("a,b,c", ",") whole = string.join(parts, "-") // "a-b-c" Prefer this over a `d = "${d}${piece}"` accumulation loop, which re-copies the whole prefix every iteration (O(n²)). For incremental building where the pieces aren't already a sequence, reach for std.strbuilder (amortized append). Result is @heap (caller-owned, reclaimed at scope exit).

Closure-bearing combinators (#421 — multi-sequence iteration). Each takes an Aether closure as the per-element callback. The callback params are declared `ptr` so the codegen heap-BOXES the closure (`_aether_box_closure`) into the slot; the C runtime unboxes, invokes the body with the captured env as the implicit first argument, and frees the box (+ its env) when the walk completes — so a one-shot `string.seq_map(s, |x| ...)` does not leak the closure. version_compare fn

version_compare(a, b) -> int

a: string, b: string

Version-aware comparison with GNU `sort -V` (coreutils/gnulib filevercmp) semantics. Returns -1 if `a` sorts before `b`, 0 if equal, 1 if after. Why this exists: plain lexical compare gets versions wrong — "clojure-1.10.jar" sorts BEFORE "clojure-1.9.jar" because '1' == '1' then '0' < '9'. version_compare compares runs of digits NUMERICALLY, so 1.9 < 1.10 and 1.11 < 1.11.1, and it is file-extension aware so whole filenames sort right too. A build tool picking the newest jar off disk (the `ls … | sort -Vr | head -1` idiom) can now do it in-process: newest = matches[0] i = 1 while i < n { if string.version_compare(matches[i], newest) > 0 { newest = matches[i] } i = i + 1 } This is the exact gnulib algorithm, so it matches `sort -V` byte-for-byte (its own verdict — plain `sort -V` adds a final whole-line lexical tiebreak that filevercmp itself does not; here 1.0 and 1.00 compare EQUAL): - digit runs compare numerically, leading zeros ignored (1.9 < 1.10) - '~' sorts before EVERYTHING including end-of-string (1.0~rc1 < 1.0) - letters sort before other punctuation, which sorts after a letter and after end-of-string (1.0 < 1.0a < 1.0-x; a release before its own "-rc") - a trailing file extension is split off and the base compared first, so clojure-1.11.jar < clojure-1.11.1.jar (".jar" stripped, 1.11 < 1.11.1) Binary-safe over bytes. Allocates nothing (indexes both strings in place). Fuzzed to zero disagreements with `sort -V -s` over thousands of random version/filename pairs. The one intentional deviation is a LEADING '.': gnulib gives dotfiles bespoke hidden-file ordering (for `ls`), which a version comparator has no business replicating — here a leading '.' is just ordinary punctuation, still yielding a stable total order. Targets version strings and artifact filenames (which never start with '.'), not hidden-file listings. CAVEAT — this compares the WHOLE string, prefix first. To pick "newest by version" across names, every candidate must share one prefix, or the prefix decides before the version does. Two footguns: - Pass BASENAMES, not full paths: "/a/x-2.jar" vs "/b/x-9.jar" compares the directory ("/a" < "/b") before the version. Use path.basename first. - Partition by artifact FAMILY before max-ing: "groovy-" sorts before "groovy-all-", so version_compare("groovy-4.0.jar","groovy-all-2.4.jar") is < 0 — it calls the OLDER -all jar "greater" on the prefix alone. Keep one family (all the groovy-all-*, else all the groovy-*), THEN max within it, where the prefix is constant and only the version varies.

aether_string_raw_ptr extern

aether_string_raw_ptr(s) -> ptr

s: ptr

The raw data pointer behind `s`, whatever its representation (a plain literal or a heap AetherString* — unwrapped the same way every other FFI accessor in this module is). Exposed so `bytes()` below can bound it; reach for `bytes(s)`, not this, unless you specifically need the bare pointer.

bytes fn

bytes(s) -> byte[]

s: string

A bounded, READ-ONLY byte[] view of s's own bytes, for binary/ASCII scanning (indexing, sub-slicing) without re-measuring the string on every access the way string_char_at_n's separate known_length parameter does. BORROWED: valid only as long as `s` itself is, exactly like any slice over someone else's storage — do not free it, and do not write through it (an AetherString's payload is shared via its refcount; a byte[] has no way to mark that sharing const, so treat this view as read-only by convention).

array_view fn

array_view(arr) -> string[]

arr: ptr

A bounded, OWNED string[] snapshot of a native string-array handle's contents (as returned by `string_split` et al.) — each element is an independently owned, refcounted copy (the `string.concat(x, "")` idiom documented above `string_array_get`), so the result safely outlives the array: call `string_array_free(arr)` right after this returns. Prefer `string_split_to_seq` when you don't need array/index shape at all; this exists for call sites that do, without inheriting the array's borrowed- pointer lifetime hazard.

seq_from_strings fn

seq_from_strings(items) -> *StringSeq

items: string[]

Build a *StringSeq from a plain string[] (e.g. a runtime slice that isn't a `[...]` literal, where the compiler's own literal-to-seq lowering does not apply). Built tail-first so the result preserves items' order; string_seq_cons takes its own reference to each element, so items itself is left untouched and may be freed/reused independently afterward.

seq_to_strings fn

seq_to_strings(s) -> string[]

s: *StringSeq

The reverse: an OWNED string[] snapshot of a *StringSeq's elements, each independently copied (same ownership idiom as array_view above), so the result does not alias the sequence's own cells. Walks the seq directly — it does not go through the AetherStringArray handle string_seq_to_array returns, since that handle is its own opaque type, not a raw string[].
