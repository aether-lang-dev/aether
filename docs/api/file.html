open fn

open(path, mode) -> (ptr, string)

path: string, mode: string

Open a file. Returns (handle, "") on success, (null, error) on failure.

close fn

close(handle) -> string

handle: ptr

Close a handle `open` gave, and free it. Returns "" on success, or the reason: a write the close flushes can fail, and the data is then not on disk (#3179).

read_all fn

read_all(handle) -> (string, string)

handle: ptr

Read the whole of an open handle, from its start. Returns (text, "") on success, ("", error) on failure; the handle stays open (#3179).

read fn

read(path) -> (string, string)

path: string

Read the entire contents of a file at `path`. Opens, reads, closes. Returns (content, "") on success, ("", error) on failure. This is the convenience form most callers want.

write fn

write(path, content) -> string

path: string, content: string

Write `content` to a file at `path`. Opens in write mode, writes, closes. Returns "" on success, error string on failure.

delete fn

delete(path) -> string

path: string

Delete the file at `path`. Returns "" on success, error on failure.

size fn

size(path) -> (_0, string)

path: string

Return the size of the file at `path` in bytes, as `long` (#1021 — files >= 2 GiB used to wrap negative through the old int surface). Returns (size, "") on success, (0, error) on failure. The success arm returns FIRST: the first `return` statement pins the inferred tuple slot types, so the `long`-typed arm must come before the int-literal error arm or the size slot narrows back to int.

fd fn

fd(handle) -> int

handle: ptr

The OS-level file descriptor inside an open handle, or -1 on a null handle (#1003). Exists for capability plumbing: open through the stdlib, then narrow the descriptor with capsicum.rights_limit(file.fd(handle), ...) before capsicum.enter(). The fd is owned by the handle — do not close it directly; it is released by close, which also frees the handle itself, so never call fd() on a handle that has been closed.
