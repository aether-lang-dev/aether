schema

std.schema — declarative, typed data validation & coercion.

import std.schema

STR const

STR = 0

---- Field type tags ----

INT const

INT = 1

FLOAT const

FLOAT = 2

BOOL const

BOOL = 3

OBJECT const

OBJECT = 4

A field holding fields of its own: a nested record. Declare them in the field's block, as in record()'s.

array fn

array(item_type) -> int

item_type: int

The type of a list of T. Rules in the field's block count its items (min/max/len/present); rules for the items go in items(), and an array of OBJECT takes the item record's fields directly in its block.

record fn

record() -> ptr

record() { field(...) ... } — the top-level container. Its trailing block runs immediately and populates the schema via field() calls.

field fn

field(_ctx, name, ty) -> ptr

_ctx: ptr, name: string, ty: int

field(name, type) { min(...); max(...); ... } Container-with-config-block: appends a Field to the enclosing record and returns it so the trailing block's rule calls accumulate onto it. Inside an OBJECT field's block it declares one of that object's fields; inside an array(OBJECT) field's block, one of each item's.

items fn

items(_ctx) -> ptr

_ctx: ptr

items() { rules }: the rules each item of an array field is checked against, where the field's own rules count the items. For an array of OBJECT, declare the item's fields directly in the field's block instead.

min fn

min(_ctx, n)

_ctx: ptr, n: long

numeric: value >= n | STR: length >= n

max fn

max(_ctx, n)

_ctx: ptr, n: long

numeric: value <= n | STR: length <= n

len fn

len(_ctx, lo, hi)

_ctx: ptr, lo: long, hi: long

STR length in [lo, hi]

present fn

present(_ctx)

_ctx: ptr

non-empty (STR) / present in input

optional fn

optional(_ctx)

_ctx: ptr

mark field optional (absence is not an error; rules skipped when absent)

one_of fn

one_of(_ctx, set)

_ctx: ptr, set: string

value must be one of a comma-separated set, e.g. one_of("admin,user")

email fn

email(_ctx)

_ctx: ptr

value must look like an email

refine fn

refine(_ctx, predicate)

_ctx: ptr, predicate: fn

custom predicate: fn(value: string) -> int (1 = ok, 0 = fail)

default_to fn

default_to(_ctx, v)

_ctx: ptr, v: string

Supply a value when the field is absent from the input (implies optional: an absent field is filled with `v` rather than erroring). A present field is validated normally; the default only fires on absence.

positive fn

positive(_ctx)

_ctx: ptr

nonneg fn

nonneg(_ctx)

_ctx: ptr

numeric >= 0

pattern fn

pattern(_ctx, spec)

_ctx: ptr, spec: string

Lightweight string pattern match without a regex dependency. `spec` is "kind:needle" where kind is one of contains / prefix / suffix, e.g. pattern("prefix:SAVE") or pattern("contains:@"). For full regex, use refine().

parse fn

parse(schema_ptr, input) -> (ptr, ptr)

schema_ptr: ptr, input: ptr

parse(schema, input_map) -> (values_map, errors_list) input_map: *Map of string(field name) -> string(raw value) values_map: *Map of field name -> coerced string value (canonical form) errors_list: *List of *SchemaError (empty on success) Both returns are always non-null and owned by the caller (values_free / errors_free). A flat map cannot carry an OBJECT or array field: one given here is an invalid_type error; use parse_json.

parse_json fn

parse_json(schema_ptr, root) -> (ptr, ptr)

schema_ptr: ptr, root: ptr

parse_json(schema, root) -> (values, errors_list) root: a std.json object (json.parse's result) values: a std.json object of the fields that passed, coerced to their types: STR a string, INT an integer, FLOAT a number, BOOL a boolean, OBJECT an object of its own fields, array(T) an array errors_list: as parse's, each error's field its path from the root: "address.city", "tags[2]", "lines[0].qty" Both returns are non-null and owned by the caller: json.json_free(values) and errors_free(errors). A JSON null is an absent field. Keys the schema does not declare are left out of values. In lax mode (the default) a string holding a number or boolean is coerced, and a number or boolean given for a STR field is taken as its text; strict mode refuses both.

to_json_schema fn

to_json_schema(schema_ptr) -> string

schema_ptr: ptr

to_json_schema(schema) -> owned JSON string (draft-07). Caller frees with string_free. Built directly with strbuilder (no JSON DOM) so it is leak-clean by construction and carries no ownership entanglement. An OBJECT field is a nested "object" schema; an array field is "array" with its "items" schema, its counting rules as minItems/maxItems.

The values map now OWNS each stored value (parse stores coerced/transformed/ defaulted strings via map_put_string_owned). map_free reclaims both the spine and every owned value.
