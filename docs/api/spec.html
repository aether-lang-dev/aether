spec

std.spec — BDD-style test framework for Aether A describe / it / before_each / after_each spec framework built on Aether's trailing blocks + closures + the `_ctx` builder context-injection pattern, with a flat assertion layer, a fluent (subject-first, chainable) assertion facade, string-list collection matchers, and Duration-budget timing checks.

import std.spec

init fn

init() -> ptr

Build a fresh framework context. Holds the test-run counters (passed / failed / skipped) as refs. The caller threads the returned ptr through every spec.* call; the suite contexts created by describe() carry it as an inner field. Also stamps the run-start timestamp + a per-it() record list + a "current_it" pointer-cell. These exist whether or not structured reporting is requested — the cost is bounded (a list of small maps, one per it()) and they feed run_summary's report when AE_SPEC_FORMAT is set. When no format is requested (`ae run foo.ae` from a terminal), run_summary doesn't read them and they get freed at exit.

it_within fn

it_within(_ctx, description, budget, test_fn)

_ctx: ptr, description: string, budget: Duration, test_fn: fn

it_within(_ctx, description, budget, test_fn) — an it() that also fails if the test body takes longer than `budget`. The budget check is layered on top of the normal assertion-based pass/fail: a body that asserts cleanly but runs over budget still goes red. Uses the same monotonic elapsed the report already records, so there's no extra measurement. `budget` is a Duration literal (`50ms`, `2s`).

it_when fn

it_when(_ctx, cond, description, reason, test_fn)

_ctx: ptr, cond: int, description: string, reason: string, test_fn: fn

it_when(cond, description, reason, test_fn) — run the body only when `cond` is non-zero; otherwise report a skip carrying `reason`. The condition is a plain int the caller computes, so the probe stays visible at the call site rather than hidden behind a predicate: have_ruby = ruby.ruby_init_host() == 0 spec.it_when(have_ruby, "evaluates", "libruby not loadable") callback { ... } `reason` is REQUIRED even on the true path, where it is unused: Aether cannot give it a default because a defaulted parameter may not precede a non-defaulted one, and the trailing-block `callback` always occupies the last slot. Pass "" when the condition is a constant true. test_fn is CALLED here rather than forwarded, for the closure-env reason documented on it().

skip_it fn

skip_it(_ctx, description, reason, test_fn)

_ctx: ptr, description: string, reason: string, test_fn: fn

skip_it(description, reason, test_fn) — an it() that never runs. For a PERMANENT exclusion (a known-broken path, an unsupported platform) where the body is kept for the day it is re-enabled. Use it_when for dependency gating; an unconditional skip that is really a missing dependency hides the provisioning gap.

skip_all_if fn

skip_all_if(fw, cond, reason) -> int

fw: ptr, cond: int, reason: string

skip_all_if(fw, cond, reason) — file-level bail-out. Returns 1 when the caller should stop (and has already printed the notice), 0 to proceed: if spec.skip_all_if(fw, have_ruby == 0, "libruby not loadable") == 1 { return } NB `cond` is evaluated eagerly by the caller, so an expensive probe still runs. When the probe IS the dependency check that is exactly right; when it is costly, guard the probe itself.

assert_eq_long fn

assert_eq_long(actual, expected, msg)

actual: long, expected: long, msg: string

64-bit sibling of assert_eq. Passing a long to assert_eq narrows it to int at the call boundary, which on a 64-bit-clean value is not merely a wrong comparison — it corrupted the caller badly enough to abort the process on Windows (exit 127) while passing on Linux, where the truncated halves happened to agree. Anything wider than 32 bits — a mem.get_long, a u64 accessor, an IEEE 754 bit pattern — needs this.

assert_str_eq_diff fn

assert_str_eq_diff(actual, expected, msg)

actual: string, expected: string, msg: string

assert_str_eq_diff(actual, expected, msg) — exact string equality like assert_str_eq, but on mismatch the message shows the two values aligned with a caret under the first differing byte (Jest/Vitest style). Reach for this over assert_str_eq when the strings are long enough that "expected X got Y" buries the actual difference. The caret column is fixed: the value lines are printed as " actual: \"" + value whose prefix is 19 chars (8 spaces + 'actual: "'), so the caret pads to 19 + index. ASCII byte index, not codepoint — fine for the ASCII test output this targets; a multibyte value just points at the first differing byte.

expect_elapsed_under fn

expect_elapsed_under(elapsed_ns, budget, msg)

elapsed_ns: long, budget: Duration, msg: string

Timing-budget matcher expect_elapsed_under(elapsed_ns, budget, msg) — a measured span is under a budget written as a Duration literal. The caller measures the span itself with two monotonic-clock reads: t0 = os.now_monotonic_ns() ... do work ... elapsed = os.now_monotonic_ns() - t0 spec.expect_elapsed_under(elapsed, 50ms, "fast path") `elapsed_ns` is a plain int64 nanosecond count (what monotonic-ns deltas yield); `budget` is a Duration (`50ms`, `2s`, `200us`). We compare in ns via budget.ns — Duration-vs-plain-number is a type error in Aether, so the .ns accessor is the bridge. Use monotonic (not wall-clock) deltas: only the delta is meaningful and a wall jump would corrupt it. The budget renders directly via ${budget} (Duration interpolation picks the largest readable unit — `50ms`, `1.5s`); the elapsed side is a plain ns count, so we show it as ms.

expect_str fn

expect_str(v) -> StrSubject

v: string

expect_str COPIES v into the subject (the chain outlives the call, and a caller temporary would be a use-after-free — valgrind confirms borrowing reads freed memory under current semantics). The copy is REGISTERED on the ambient framework's "str_copies" list so run_summary's teardown releases it: the chain has no terminal hook (every link returns the subject), so end-of-run is the only safe release point. Without an init()'d framework the copy is untracked — same single-framework tradeoff as fail() itself.

satisfies fn

satisfies(s, pred, msg) -> IntSubject

s: IntSubject, pred: fn, msg: string

satisfies(s, pred, msg) — fluent escape hatch (AssertJ-style). `pred` takes the subject's value and returns 1 (ok) / 0 (fail). Lets a test drop into an arbitrary one-off check mid-chain without defining a whole new matcher: spec.expect_int(n).to_be_gt(0).satisfies(is_prime, "is prime") `pred` is a top-level fn passed by bare name. One satisfies() per subject type — Aether has no receiver-type overloading.
